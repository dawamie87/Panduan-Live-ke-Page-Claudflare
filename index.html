Unggah kode ke GitHubTempat kode aplikasi disimpan

Cara mudah (lewat browser)

  1. Buka github.com/new (atau klik tanda + di kanan atas GitHub → New repository).
  2. Isi Repository name (contoh nama-aplikasi). Pilih Private bila kode tidak ingin dilihat umum (Cloudflare tetap bisa membacanya setelah Anda beri izin).
  3. Klik Create repository, lalu pilih uploading an existing file.
  4. Seret semua file aplikasi (index.html, folder css, js, dst.) ke halaman itu, lalu klik Commit changes.

Siapkan SupabaseDatabase, tabel profil, dan keamanan

2.1 Buat project

  1. Masuk ke supabase.com/dashboard → New project.
  2. Isi nama project, buat Database Password yang kuat (simpan!), pilih region terdekat (mis. Singapore).
  3. Tunggu 1–2 menit sampai project aktif.

  2. Salin Project URL dan kunci anon / publishable.
  3. Buat file config.js di repository GitHub Anda:
config.js

2.3 Jalankan SQL dasar

Buka SQL Editor → New query, tempel, lalu klik Run. SQL ini membuat tabel profil, mengisinya otomatis saat ada yang login, dan mengaktifkan RLS (pengaman per baris).

SQL 
-- Tabel profil pengguna
create table if not exists public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text unique,
  nama text,
  foto_url text,
  role text not null default 'user' check (role in ('admin','user')),
  created_at timestamptz default now()
);

alter table public.profiles enable row level security;

-- Otomatis buat profil saat pengguna pertama kali login
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = public
as $$
begin
  insert into public.profiles (id, email, nama, foto_url)
  values (
    new.id,
    new.email,
    new.raw_user_meta_data->>'full_name',
    new.raw_user_meta_data->>'avatar_url'
  )
  on conflict (id) do nothing;
  return new;
end;
$$;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();

-- Fungsi cek admin
create or replace function public.is_admin()
returns boolean
language sql
security definer
set search_path = public
stable
as $$
  select exists (
    select 1 from public.profiles
    where id = auth.uid() and role = 'admin'
  );
$$;

-- Aturan akses
create policy "Baca profil sendiri" on public.profiles
  for select to authenticated using (auth.uid() = id);

create policy "Admin baca semua profil" on public.profiles
  for select to authenticated using (public.is_admin());

2.4 Jadikan Gmail Anda sebagai admin

Lakukan setelah Anda berhasil login pertama kali (Langkah 5), lalu jalankan:

SQL 
update public.profiles
set role = 'admin'
where email = 'emailanda@gmail.com';
💡
Setiap tabel baru yang Anda buat untuk aplikasi (data pegawai, transaksi, dll.) wajib diaktifkan RLS-nya dan diberi policy. Tanpa RLS, siapa pun yang memegang kunci publik bisa membaca datanya.

Mengapa RLS penting?

🔓Tanpa RLS

Siapa pun yang memegang kunci publik bisa membaca semua baris di tabel.

🔒Dengan RLS + policy

Setiap pengguna hanya melihat baris miliknya, atau sesuai peran (mis. admin).

⏸️
Paket gratis Supabase: project yang tidak aktif cukup lama dapat dijeda otomatis. Bila aplikasi tiba-tiba tidak bisa login atau memuat data, buka dashboard Supabase dan klik Restore. Untuk aplikasi yang dipakai harian (mis. absensi), pertimbangkan paket berbayar atau pastikan ada aktivitas rutin. Lakukan juga backup data penting secara berkala.
Opsional: hanya Gmail tertentu yang boleh masuk (daftar putih)

Berguna bila aplikasi hanya untuk pegawai/anggota tertentu. Tambahkan tabel daftar email, lalu gunakan fungsi ini pada policy tabel data Anda.

SQL 
create table if not exists public.email_diizinkan (
  email text primary key
);
alter table public.email_diizinkan enable row level security;

insert into public.email_diizinkan (email) values
  ('emailanda@gmail.com'),
  ('rekan@gmail.com');

create or replace function public.is_allowed()
returns boolean
language sql
security definer
set search_path = public
stable
as $$
  select exists (
    select 1 from public.email_diizinkan
    where lower(email) = lower(auth.jwt()->>'email')
  );
$$;

Aktifkan login dengan GmailGoogle OAuth + Supabase Auth

🧭
Urutan penting: (A) catat alamat callback dari Supabase → (B) buat kunci di Google → (C) tempel kunci ke Supabase → (D) daftarkan alamat situs.

Alur login: apa yang terjadi saat tombol ditekan?

🖱️Klik tombolPengguna menekan "Masuk dengan Google"
🔐Pilih akun GmailLayar resmi Google meminta izin
🔁Callback ke SupabaseGoogle mengirim bukti login ke alamat callback
🎟️Sesi dibuatSupabase membuat sesi dan mengembalikan pengguna ke situs Anda
✅Berhasil masukAplikasi menampilkan nama dan foto pengguna

A. Catat alamat callback Supabase

  1. Di Supabase buka Authentication → Sign In / Providers → Google.
  2. Salin Callback URL (for OAuth). Bentuknya:
callback 
https://PROJECT-REF.supabase.co/auth/v1/callback

B. Buat OAuth Client di Google Cloud

  1. Buka console.cloud.google.com, buat project baru (mis. "Aplikasi Saya").
  2. Menu APIs & Services → OAuth consent screen (atau Google Auth Platform). Pilih External, isi nama aplikasi, email dukungan, dan email kontak developer.
  3. Di bagian scope, cukup openid, email, profile (bawaan, tidak perlu verifikasi Google).
  4. Buka halaman Credentials → Create Credentials → OAuth client ID → tipe Web application.
  5. Authorized JavaScript origins – tambahkan alamat situs:
Authorized JavaScript origins 
https://nama-aplikasi.pages.dev
http://localhost:5500
  1. Authorized redirect URIs – tempel callback dari langkah A:
Authorized redirect URIs 
https://PROJECT-REF.supabase.co/auth/v1/callback
  1. Klik Create, lalu salin Client ID dan Client Secret.
🟡
Status aplikasi "Testing" hanya mengizinkan test users yang Anda daftarkan. Agar semua Gmail bisa masuk, ubah ke In production di halaman OAuth consent / Audience. Dengan scope dasar tadi, tidak perlu proses verifikasi.

C. Masukkan kunci ke Supabase

  1. Kembali ke Authentication → Sign In / Providers → Google.
  2. Aktifkan Enable Sign in with Google.
  3. Tempel Client ID dan Client Secret, klik Save.

D. Daftarkan alamat situs di Supabase

  1. Buka Authentication → URL Configuration.
  2. Site URL: isi alamat produksi Anda.
  3. Redirect URLs: tambahkan semua alamat yang boleh menerima pengguna setelah login.
URL Configuration

Redirect URLs:
https://nama-aplikasi.pages.dev/**

Baris kedua (*-nama) berguna agar alamat preview Cloudflare ikut berfungsi. Bila ragu, tambahkan dulu alamat utama saja.

E. Kode tombol "Masuk dengan Google"

Tempel ke index.html. Memakai library resmi supabase-js lewat CDN, jadi tidak perlu build.

index.html 
<!doctype html>
<html lang="id">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Aplikasi Saya</title>
  <script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
  <script src="config.js"></script>
</head>
<body>
  <div id="login">
    <h1>Selamat datang</h1>
    <button id="btnLogin">Masuk dengan Google</button>
  </div>

  <div id="app" hidden>
    <p>Halo, <b id="nama"></b> (<span id="email"></span>)</p>
    <button id="btnLogout">Keluar</button>
  </div>

  <script>
    const { createClient } = supabase;
    const db = createClient(APP_CONFIG.SUPABASE_URL, APP_CONFIG.SUPABASE_KEY);

    document.getElementById('btnLogin').onclick = () =>
      db.auth.signInWithOAuth({
        provider: 'google',
        options: { redirectTo: window.location.origin }
      });

    document.getElementById('btnLogout').onclick = () => db.auth.signOut();

    function tampil(session) {
      const masuk = !!session;
      document.getElementById('login').hidden = masuk;
      document.getElementById('app').hidden = !masuk;
      if (masuk) {
        const u = session.user;
        document.getElementById('nama').textContent =
          u.user_metadata.full_name || u.email;
        document.getElementById('email').textContent = u.email;
      }
    }

    db.auth.getSession().then(({ data }) => tampil(data.session));
    db.auth.onAuthStateChange((_event, session) => tampil(session));
  </script>
</body>
</html>

Pasang domain sendiriOpsional: ganti pages.dev dengan aplikasi.domainanda.com

🧑‍💻Pengunjung mengetikapp.domainanda.com

☁️Cloudflare menyajikanIsi situs diambil dari project Pages Anda
🔒HTTPS otomatisSertifikat dibuat gratis oleh Cloudflare
🧭
Pastikan situs sudah berhasil tayang di pages.dev dan login Gmail sudah berjalan sebelum memasang domain. Jadi bila ada masalah, mudah dipisahkan penyebabnya.

Pilih skenario Anda

A. SubdomainContoh app.domainanda.com. Paling mudah, DNS boleh tetap di penyedia domain lama (cukup tambah satu rekaman CNAME).
B. Domain utamaContoh domainanda.com. Cloudflare Pages mensyaratkan DNS domain dikelola Cloudflare, jadi nameserver perlu dipindah.

Skenario A: subdomain (DNS tetap di penyedia lama)

  1. Di Cloudflare buka Workers & Pages → pilih project Anda → tab Custom domains → Set up a custom domain.
  2. Ketik subdomain, contoh app.domainanda.com, lalu lanjutkan.
  3. Cloudflare akan menampilkan rekaman DNS yang harus dibuat. Masuk ke panel DNS penyedia domain Anda (Niagahoster, Rumahweb, Domainesia, GoDaddy, dll.) lalu tambahkan:
TypeName / HostTarget / Value
CNAMEappnama-aplikasi.pages.dev
  1. Kembali ke Cloudflare dan klik Check DNS records / Activate domain. Status akan berubah dari Pending menjadi Active (biasanya beberapa menit, kadang hingga 24 jam).
  2. Sertifikat HTTPS dibuat otomatis oleh Cloudflare, tidak perlu beli SSL.

Skenario B: domain utama (pindah DNS ke Cloudflare)

  1. Di Cloudflare klik Add a domain (menu utama dashboard), masukkan domainanda.com, pilih paket Free.
  2. Cloudflare memindai rekaman DNS lama. Periksa dan pastikan semua rekaman penting ikut (terutama MX bila Anda memakai email domain) agar email tidak putus.
  3. Cloudflare memberi dua nameserver (mis. xxx.ns.cloudflare.com). Masuk ke panel penyedia domain → Nameserver / DNS Management → ganti nameserver lama dengan dua nameserver tersebut.
  4. Tunggu sampai Cloudflare menandai domain Active (bisa beberapa menit hingga 24 jam).
  5. Buka project Pages → Custom domains → Set up a custom domain → isi domainanda.com. Cloudflare membuat rekaman DNS-nya otomatis.
  6. Agar www ikut bekerja, tambahkan www.domainanda.com sebagai custom domain kedua, lalu arahkan salah satunya ke yang lain lewat Rules → Redirect Rules (disarankan www diarahkan ke domain utama).
⚠️
Memindah nameserver memengaruhi semua layanan di domain itu (website lain, email). Bila domain Anda sudah dipakai website atau email aktif, lebih aman memakai Skenario A dengan subdomain.

Uji domain baru

  1. Buka https://app.domainanda.com di jendela incognito. Pastikan ada ikon gembok (HTTPS).
  2. Klik Masuk dengan Google, pilih akun, dan pastikan Anda kembali ke domain baru dalam keadaan sudah masuk.
  3. Bila gagal, lihat bagian Masalah umum di bawah.
Domain tetap "Pending" / "Verifying" terlalu lama

Periksa rekaman CNAME sudah tepat (nama host hanya app, bukan app.domainanda.com pada sebagian panel). Pada Skenario B, pastikan nameserver di penyedia domain sudah benar-benar berganti. Perubahan DNS dapat memakan waktu hingga 24 jam.

Muncul error SSL / "Too many redirects"

Di Cloudflare buka SSL/TLS → Overview dan gunakan mode Full (atau Full strict). Hindari mode Flexible untuk situs Pages karena dapat menyebabkan pengalihan berulang.

Login mengarah kembali ke pages.dev bukan domain baru

Periksa Site URL di Supabase sudah diganti ke domain baru, dan redirectTo di kode memakai window.location.origin (seperti pada contoh kode di Langkah 3E).

Domain didaftarkan di Niagahoster/Rumahweb/Domainesia, apakah bisa?

Bisa. Domain boleh dibeli di mana saja. Untuk subdomain cukup tambah CNAME di panel DNS mereka. Untuk domain utama, ganti nameserver ke Cloudflare di menu pengaturan nameserver domain tersebut.

?

Masalah umumKlik untuk melihat solusi

redirect_uri_mismatch dari Google

Alamat callback di Authorized redirect URIs Google harus sama persis dengan yang ditampilkan Supabase (https://PROJECT-REF.supabase.co/auth/v1/callback), tanpa spasi atau garis miring tambahan. Perubahan di Google kadang butuh beberapa menit.

Setelah login malah kembali ke localhost atau alamat yang salah

Periksa Site URL dan Redirect URLs di Supabase (Langkah 3D). Pastikan alamat pages.dev tercantum dan redirectTo di kode memakai window.location.origin.

"Access blocked: app has not completed verification"

Aplikasi masih berstatus Testing. Tambahkan Gmail Anda sebagai Test user, atau ubah status ke In production di halaman OAuth consent / Audience.

Login sukses tapi data tidak muncul / error "permission denied"

Hampir pasti karena RLS: tabel sudah diaktifkan tetapi belum diberi policy untuk select/insert. Tambahkan policy untuk role authenticated sesuai kebutuhan.

Halaman putih / 404 di Cloudflare

Periksa Build output directory. Bila index.html berada di dalam folder (mis. public), isi kolom itu dengan nama folder tersebut. Pastikan file bernama persis index.html (huruf kecil).

Perubahan di GitHub belum terlihat

Lihat Deployments di project Pages untuk memastikan build selesai, lalu muat ulang paksa (Ctrl+Shift+R). Pastikan perubahan ada di branch main.

Ingin membatasi hanya email kantor/sekolah tertentu

Gunakan daftar putih di Langkah 2.3 (opsional), atau ubah policy agar memeriksa domain email, mis. auth.jwt()->>'email' like '%@sekolahanda.sch.id' (hanya berlaku bila akun Google tersebut memang memakai domain itu).
